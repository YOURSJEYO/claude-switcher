# 官方版本免费与举报提醒设计

## 目标

在 macOS 菜单栏 App 首次启动主窗口时提醒用户：官方版本免费；冒充官方收费、删除许可证、隐瞒修改或不提供 AGPL 对应源码的发行行为欢迎举报。用户确认后不再自动弹出，但可以从主窗口信息按钮和菜单栏随时再次查看。

## 范围

- 修改 `app/main.swift` 的 SwiftUI 视图、AppDelegate 启动状态和菜单栏入口。
- 修改 `tests/MenuBarModelTests.swift` 覆盖首次显示、确认后抑制和手动入口可用所需的可测试模型行为。
- 更新 `tests/MENU-BAR-TESTING.md` 的隔离验收步骤。
- 不修改安装器、核心脚本、守护进程、真实安装态、账号数据或系统设置。

## 交互设计

启动后主窗口正常显示并开始环境检查，同时显示一次公告 Sheet。公告包含：

1. 官方版本免费提供，维护者不出售官方安装包或账号服务。
2. 不得冒充官方、维护者或授权渠道销售官方版本。
3. 删除许可证、隐瞒修改、不给对应源码或施加冲突限制属于举报范围。
4. AGPL-3.0-only 允许在履行义务的前提下再分发和收费，因此单纯收费不自动等于违规。
5. 举报入口指向项目 Issues（https://github.com/YOURSJEYO/claude-switcher/issues），并要求附商品链接、截图和版本信息；提醒不要公开个人信息、订单信息和账号凭据。

公告只显示一次。确认按钮记录 `UserDefaults` 中的布尔值；后续启动、关窗后重开和菜单栏打开主窗口都不会再次自动弹出。信息按钮继续打开现有安全公告；新增的专用菜单项直接打开本公告，方便用户复看。

## 组件与接口

- `OfficialReleaseNoticeView`: 独立 SwiftUI Sheet，负责公告内容、关闭按钮和 Issue 链接。
- `OfficialReleaseReminder`: `UserDefaults` 键名常量和读写方法，集中定义“已读”状态，避免视图和 AppDelegate 各自散落字符串。
- `AppDelegate`: 在首次创建并展示主窗口后，根据 `OfficialReleaseReminder` 决定是否触发展示；确认回调写入已读状态。
- `MenuBarContent`: 增加“官方版本免费与举报”菜单项，打开主窗口并展示公告。

## 生命周期与状态

- 首次启动：创建窗口、显示窗口、启动 VM 检查，并异步显示公告 Sheet，避免抢占窗口创建时机。
- 已读启动：创建窗口、显示窗口、启动 VM 检查，不显示公告。
- 手动查看：无论是否已读，都显示公告；手动关闭不改变自动提醒以外的运行状态。
- 测试：使用独立 `UserDefaults` suite 或注入存储，确保测试不污染真实用户偏好。

## 错误与边界

- Issue 链接无法打开时不影响公告关闭和 App 使用。
- App 关闭窗口只是隐藏，重开窗口不重复触发首次提醒。
- 提醒不得阻断环境检查、账号切换、退出保护或菜单栏驻留。

## 验证

- Swift 模型测试验证首次启动只产生一次提醒状态、确认后状态持久化、已读状态抑制后续自动提醒。
- 现有菜单栏模型测试保持通过。
- 在 macOS 13+ 上编译 `MenuBarFixture` 做隔离 UI 验收：首次启动有提醒；确认后关闭；菜单栏“官方版本免费与举报”可再次打开。
- Linux/Windows 与核心脚本测试不受此次 UI 改动影响。
